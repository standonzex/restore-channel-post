# Restore Channel Post — 1.8

Восстановление удалённого поста канала через «Недавние действия»: возвращается исходный объект с прежним ID, датой, временем и местом в ленте. Окно восстановления — 48 часов с момента удаления, даже если пост опубликован несколько лет назад.

В комплекте — работающие самостоятельные iPhone- и Mac-приложения, общий Swift-модуль, постоянный локальный сервер Python/SQLite, тесты и отдельный патч существующего экрана Telegram iOS. Это референсная реализация; для настоящих каналов нужна серверная поддержка Telegram. Полный Telegram-клиент с патчем не собран и не запущен. Точный статус — CODE-STATUS.md.

## Запуск iPhone

Распаковать исходники и открыть терминал в папке RestoreChannelPost. Нужны Mac, полный Xcode и запущенный iPhone Simulator:

```sh
./build-ios-demo.sh
./run-ios-demo.sh
```

Оставить терминал с сервером открытым. Свежая база пустая; существующая сохраняется. info внизу → очистить только синтетический канал или загрузить старые примеры. Ввести текст и отправить его либо удержать кнопку камеры и отправить подготовленный кружок. Затем: удержать пост → «Удалить» → «Удалить у всех» → название канала → «Изм.» → прокрутить до «Недавних действий» → удержать карточку → «Восстановить».

В старых примерах есть пост 3 апреля 2022 / 17:30: он возвращается к старой дате, перед новыми публикациями. Подробности — IOS-SETUP.md, DEMO-SCENARIO.md и submission/REVIEWER-EN.md. Камера и микрофон не записываются: видеопредпросмотр использует локальный тестовый клип.

## Запуск Mac

```sh
./build.sh
open 'dist/Restore Channel Post.app'
```

Сервер запускается и завершается вместе с Mac-приложением. Telegram-аккаунт, токен бота и облачные сервисы не нужны. EN переключает язык. «Начать показ заново» загружает синтетические примеры; настройки канала открывают журнал восстановления. Другой способ запуска — Start Demo.command.

## Проверка

```sh
./verify.sh
./build-ios-demo.sh
```

37 Python/HTTP + 14 общего Swift-модуля + 6 политики срока + 7 состояния интерфейса = 64 проверки. Дополнительно проверяются сквозной Swift–HTTP–SQLite сценарий, синтаксис нативного патча, обе самостоятельные сборки и подписи. Для применения/согласованности патча на чистой базе: RECOVERY_TELEGRAM_CHECKOUT=/path/to/Telegram-iOS ./verify.sh. Полную сборку Telegram это не заменяет. Отчёт — QA-REPORT.md.

## Что отправить

Готовый английский текст — submission/MESSAGE-EN.txt. Русский перевод — MESSAGE-RU.txt. Описание функции — FEATURE-EN.md, инструкция проверяющему — REVIEWER-EN.md. Порядок и подтверждённые условия отправки — SEND-RU.md и REQUIREMENTS-RU.md в той же папке. Комплект для передачи находится в release/contest-no-video-1.8/; финальное демовидео добавляется отдельно.

Архив исходников содержит внутренний MOV-ресурс для воспроизведения тестового кружка. Презентационные ролики, музыка, рабочие базы, секреты сессий, .env, бот Again и личные скриншоты исключены. Ничего не опубликовано публично и не отправлено адресату. Исходники можно передать приватно архивом; обязательность публичного GitHub в проверенном объявлении не указана.

## Структура

module/ — общий координатор и контракт транспорта; server/ — транзакции и локальное HTTP API; app/ и ios-demo/ — работающие хосты; ios/ — нативный патч и полные изменённые файлы; tests/ — проверки; tools/ — сборка/упаковка/проверка; submission/ — материалы для передачи.

API-CONTRACT.md и INTEGRATION.md описывают подключение со стороны Telegram. LICENSE.md и NOTICE.md сохраняют разграничение оригинального кода и Telegram-derived файлов. Принятие предложения и выпуск функции определяет Telegram.
